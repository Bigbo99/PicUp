# 图片状态与服务器缓存

## 用户看到的流程

后台负责调用渠道、取得生成结果、将图片上传至七牛。生成和上传期间，任务保持 `running`，用户看到“生成中”；七牛保存成功、结果写入任务记录后，才切换为 `succeeded`。不向用户展示“转存中”。

浏览器通过 `GET /api/image/jobs/:id` 查询任务状态。当前页面的任务每 2 秒查询一次，完成后停止常规轮询。响应中的 `outputImages` 包含图片地址；前端将展示地址映射为 `/api/image/jobs/:id/preview/:index`。预览接口先验证任务归属，再读取图片。

本次沿用现有状态链路：数据库保存任务状态，Redis 负责任务队列和执行协调。实时状态缓存与异步渠道的延迟查询调度属于后续独立改动，本次没有改成 Redis 状态查询。

## 图片缓存策略

- 七牛保存成功后，利用服务器已有的图片字节立即写入本地磁盘缓存。API 首次展示新图片无需再向七牛下载。
- 读取先查本地缓存；未命中或过期时，从七牛下载并回填。缓存放在 `STORAGE_DIR/cache/objects`，不存放在 Redis 中。
- 默认保留最近使用的最多 **1000 张**、合计最多 **1 GiB**，达到任一限制时淘汰最久未访问的图片。实际数量取决于文件大小，1000 张不是保证保留的数量。
- 每次命中刷新最近使用时间；默认 **7 天未访问**后失效。到期文件在读取或后续缓存写入清理时删除，不是精确到秒的后台清理任务。
- 同一服务进程内同时读取同一张未缓存图片时，共用一次下载。API 与 worker 不共享内存中的下载锁，但共享磁盘文件。
- 临时文件写完后再重命名为缓存文件，避免其他进程读到半张图片。批量写入会合并清理；写入期间可能短暂超过容量上限。
- 缓存删除仅删除本地副本，不删除七牛原图。缓存写入失败不会导致已成功上传的图片生成失败。
- 显式删除七牛对象时同时失效缓存；同一进程中，对同一对象的读、写、删除按顺序执行，避免正在下载的旧图片重新填回缓存。

API 和 worker 必须挂载同一份 `storage` 目录，现有 `docker-compose.yml` 已如此配置。如果以后部署到多台机器，每台机器会拥有自己的磁盘缓存及容量额度。

## 配置

```dotenv
OBJECT_CACHE_MAX_FILES=1000
OBJECT_CACHE_MAX_BYTES=1073741824
OBJECT_CACHE_TTL_SECONDS=604800
```

任一项设为 `0` 可关闭缓存读写；已有磁盘副本不会立即批量删除。单张图片大于总容量额度时，不缓存该图片。参数非法或留空时使用默认值。修改环境变量后需重建/重启相应的 API 与 worker 容器以加载配置。

图片预览接口还保留现有的浏览器私有缓存（`private, max-age=86400, immutable`）。图片 URL 对应不可变输出，浏览器可以复用已加载的图片；缓存未命中、过期或被清理时才请求服务器。状态接口继续独立轮询，不套用图片的一天缓存。

本地缓存只减少重复从七牛下载，不保证首次冷读命中，也不会让图片处理或网络传输变成零成本。对象在七牛控制台被外部覆盖时，缓存不会自动收到通知，因此生成结果继续使用不可变对象键；通过本服务覆盖同一个对象时会更新缓存。
